## 1. Upstream PaperCSS reconciliation

The framework is consumed by reference, not vendored: `papercss.lock.json` pins the tag and digest, `head.html` loads it, and `scripts/check-papercss.mjs` enforces the match. This group settles the upstream questions the rest of the change depends on and moves the pin. Do not start groups 3-8 before 1.3 and 1.5 complete.

- [x] 1.1 **Flagged risk 1 — palette defect.** Determine the release the theme currently references (`v2.0.1`, per `papercss.lock.json`) and compare it against the latest published release (`v2.0.2`). Verify against the fetched stylesheet whether `v2.0.2` changes any palette value (the defects it could have fixed are enumerated in 1.4). Record the finding: `v2.0.2` is byte-identical to `v2.0.1` and fixes nothing.
- [x] 1.2 **Flagged risk 2 — nav reachability.** Determine whether the referenced release's `.split-nav` and `.collapsible` rules place any upper bound on nav child width, or hide the collapsible body below a breakpoint — the condition under which a two-button control in the nav would be clipped or unreachable on narrow screens. Finding: `.split-nav` sets only `justify-content:space-between` (no width bound); below 768px the nav is `display:block` and `.collapsible-body` collapses behind an absolutely-positioned hamburger. The control is therefore placed as a direct child of `<nav>`, outside `.collapsible`, so it is never hidden by the collapse; no fallback needed.
- [x] 1.3 Based on 1.1 and 1.4, choose: adopt `v2.0.2` and carry local corrections for the two reachable dark-mode defects (`--muted-text` against `.alert-muted`, and the `.background-{type}` text color), because no release fixes them. Do **not** re-declare `--primary-text` — it is unreachable in the theme's output and re-declaring it would regress `.alert-primary`. Verify the choice and its reason are written down before any override-layer edit is made.
- [x] 1.4 Audit the referenced `html.dark` palette against every class the theme's templates emit, using the release 1.3 settled on, and verify each result is listed explicitly. Finding: reachable breakages are `.alert-muted` (`#949ba2` on `#949ba2`, 1.00) and `.background-{type}` (white text on a light surface; `.background-primary` 1.00, others 1.7-3.4). `--primary-text` is not reachable (only placed on `--primary-light` surfaces). Low-but-legible values recorded as accepted: `.text-danger` 2.62, `.text-muted` 3.12, `.text-secondary` 3.24, `.badge` 3.32, and the non-primary `.alert-*`/`.background-*` variants 3.1-4.4.
- [x] 1.5 Re-pin the framework: run `make papercss-pin TAG=v2.0.2` and verify it rewrites `papercss.lock.json`, `layouts/partials/head.html`, and `README.md`. Verify `node scripts/check-papercss.mjs` passes and the recorded integrity is unchanged from `v2.0.1`, confirming the stylesheet bytes are identical. If the digest differs, stop and reconcile rather than accepting an unexplained change.
- [x] 1.6 Update the `assets/css/custom.css` header comment to name the pinned release and record the reachable dark-mode defects it still carries. Verify the comment agrees with `papercss.lock.json`.
